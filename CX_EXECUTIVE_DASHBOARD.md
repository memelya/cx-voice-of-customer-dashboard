# Документация исполнительной CX-панели

## Назначение

«Голос клиента и CX» — командный центр клиентского опыта для руководства банка. Это не корпоративный лендинг. Панель должна за 30–90 секунд ответить:

1. В каком состоянии CX сейчас.
2. Как CX менялся раньше.
3. Что улучшилось.
4. Что ухудшилось.
5. Почему это произошло.
6. Какие действия улучшат CX-метрики.
7. Где максимальный бизнес-upside.

## Логика сторителлинга

Страница следует логике руководства принятия решений:

1. **Обзор для руководства** — индекс CX, NPS, CSI, удержание, риск оттока, цифровая удовлетворённость, жалобы и время решения.
2. **Динамика CX** — квартальный/месячный тренд с наложением жалоб.
3. **Голос клиента** — главные болевые точки, объём, тренд и влияние на NPS.
4. **Клиентские пути** — здоровье онбординга, мобильного приложения, карт, платежей, поддержки, кредитов, ипотеки, отделений и колл-центра.
5. **Аналитика первопричин** — операционные, продуктовые и процессные сбои, ранжированные по влиянию.
6. **Что улучшило CX** — эффект инициатив до/после и ROI.
7. **Что делать дальше** — механизм рекомендаций и матрица приоритетов.
8. **Сегменты / каналы** — CX-риск по клиентским группам.
9. **Выводы для руководства** — ультракороткие сигналы AI-формата для правления.
10. **Будущие сценарии CX** — прогноз NPS, удержания и оттока при улучшениях.

## Синтетическая модель данных

Датасет находится в `content/cx-data.ts` и включает:

- историю NPS;
- историю CSI;
- удержание и риск оттока;
- объём жалоб;
- рейтинги приложения;
- аналитику клиентских путей;
- приближённые метрики SLA поддержки и времени решения;
- объёмы болевых точек;
- цепочки первопричин;
- эффект инициатив до/после;
- риск по сегментам и каналам;
- сценарное моделирование.

Данные синтетические, не случайные и причинно связанные. Примеры допущений:

- задержки KYC повышают отвал в онбординге и жалобы;
- время ожидания поддержки — крупнейший драйвер оттока;
- синхронизация ETA снижает жалобы на доставку карт;
- приоритетный чат улучшает удержание premium-клиентов;
- циклы документов в ипотеке повышают оценку клиентского усилия и снижают удовлетворённость.

## Дизайн-система

Визуальные принципы:

- тёмный панель руководства для первого экрана;
- светлая аналитическая зона для клиентских путей, первопричин и действий;
- высококонтрастная типографика метрик;
- компактные KPI-карточки;
- деликатный эффект стеклянных поверхностей;
- минимальные градиенты;
- табличное отображение чисел;
- сдержанная анимация;
- доступная семантическая структура.

Основной визуальный язык:

- бирюзовый = позитивная динамика / улучшение;
- розовый = ухудшение / риск;
- янтарный = предупреждение / зона наблюдения;
- синий = цифровой / продуктовый сигнал.

## Компоненты

- `DashboardShell` — композиция страницы и логика секций.
- `charts.tsx` — визуализации Recharts: мини-графики, временные ряды, радар, столбцы, матрицу приоритетов и сценарный график.
- `cx-data.ts` — синтетический датасет банковского CX.
- `utils.ts` — утилиты для className и форматирования.

## Деплой

Рекомендуемый деплой: Vercel.

Безопасный процесс:

1. Работать в `feature/cx-voice-dashboard`.
2. Проверить локально: `npm run build`.
3. Сделать commit с понятным сообщением.
4. Пуш через защищённый helper/API; не логировать токены.
5. Открыть PR в `main`.
6. Деплоить на Vercel после подтверждения.
7. Добавить GitHub URL и live URL в README после деплоя.

## Будущие расширения

- Интеграция реальных данных из опросов, app telemetry, колл-центра, CRM и систем жалоб.
- Ролевые представления для правления / CX / розничного бизнеса.
- Детализация от первопричины к клиентским дословным отзывам.
- Когортный анализ на уровне клиентских путей.
- Уведомления в реальном времени по нарушениям SLA.
- AI-сгенерированный нарратив для руководства со ссылками на доказательства.
- Сценарная модель, откалиброванная на исторической эластичности.
